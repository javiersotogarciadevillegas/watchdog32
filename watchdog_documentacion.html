🎯 ¿Qué es el Watchdog?

El Watchdog ESP32 es un dispositivo independiente que vigila continuamente que todos tus dispositivos de red (cámaras, tableros, módulos Alexa, etc.) estén respondiendo. Si detecta que alguno ha dejado de funcionar, actúa automáticamente para reiniciarlo cortando y reponiendo su alimentación eléctrica.

Es completamente autónomo — funciona sin intervención humana 24/7. Se configura una sola vez desde su página web y trabaja solo. Si el propio Watchdog se reinicia, recupera toda su configuración de la memoria NVS y retoma la vigilancia sin perder nada.

✅ El Watchdog es independiente del tablero — si el tablero se cuelga, el Watchdog puede reiniciarlo igualmente porque no depende de él para funcionar.
ℹ️ El Watchdog hace ping HTTP al endpoint /status de cada dispositivo. Cualquier respuesta HTTP (200, 401, 404...) se considera "vivo". Solo falla si no hay conexión TCP en absoluto.

🔧 Hardware necesario

🧠
ESP32 WROOM-32D o 32U
Microcontrolador principal. 32D = antena integrada / 32U = conector U.FL para antena externa. Ambos son compatibles y tienen los mismos pines.
📻
FS1000A — GPIO 4
Transmisor RF 433MHz. Se conecta a GPIO4 (RF_TX_PIN). Permite reiniciar dispositivos que escuchan señales RF.
💡
LED interno — GPIO 2
LED de estado integrado en la placa. Se enciende durante el arranque y se apaga cuando el sistema está listo.
📶
WiFi 2.4GHz + ESP-NOW
Conectado a tu red WiFi para hacer pings HTTP y servir la web. ESP-NOW para comunicación directa con tableros y cámaras.
⚠️ El FS1000A debe conectarse a GPIO4 (no a GPIO46 ni ningún otro). Es el pin definido como RF_TX_PIN en el código.

⚙️ Cómo funciona — flujo completo

Arranque del sistema

1

Inicialización

Enciende el LED de estado, carga los 16 dispositivos y la configuración global desde NVS. Si es la primera vez, usa los valores por defecto del código.

2

Conexión WiFi con IP fija

Se conecta a la red WiFi configurada aplicando la IP estática antes del WiFi.begin(). Si la IP guardada en NVS es inválida, usa 192.168.1.250 por defecto.

3

Iniciar ESP-NOW y RF

Registra los peers ESP-NOW de todos los dispositivos activos que tengan ESP-NOW habilitado. Configura el transmisor RF 433MHz en GPIO4 con protocolo 1, 10 repeticiones y pulso de 350µs.

4

Servidor web listo

Registra todas las rutas HTTP y arranca el servidor en el puerto 80. Añade una entrada al log de arranque. Apaga el LED de estado.

Ciclo principal de vigilancia

1

Esperar el intervalo configurado

Cada N segundos (por defecto 30, configurable entre 5 y 300) arranca un nuevo ciclo de ping para todos los dispositivos activos.

2

Ping HTTP a cada dispositivo

Para cada dispositivo activo con IP configurada, hace GET http://IP/status con timeout de 3 segundos. Entre pings hay una pausa de 500ms para no saturar la red.

3A

Si responde ✅

Resetea el contador de fallos a 0. Actualiza el timestamp de "último OK". Si venía de un estado de fallo, lo registra en el log.

3B

Si no responde ⚠️

Incrementa el contador de fallos. Lo registra en el log. Si el contador llega al máximo configurado (por defecto 3), actúa.

4

Actuar — enviar señal de apagado

Envía el código ESP-NOW y/o RF configurado para ese dispositivo (según checkboxes). Esto apaga el relé que alimenta el dispositivo. Marca el dispositivo como "esperando reencender".

5

Esperar tiempo de apagado

Espera los segundos configurados en "T.Apagado" (por defecto 5s). Durante este tiempo el dispositivo está sin alimentación.

6

Reencender — enviar señal de encendido

Envía de nuevo el mismo código ESP-NOW y/o RF (toggle = enciende). Resetea el contador de fallos. Entra en período de gracia.

7

Período de gracia 🛡️

Durante el tiempo configurado en "T.Gracia" (por defecto 90s), no se vigila ese dispositivo. Esto da tiempo al dispositivo a arrancar completamente sin que el Watchdog lo vuelva a reiniciar.

8

Vigilancia reanudada

Fin del período de gracia. El dispositivo vuelve a ser vigilado normalmente en el siguiente ciclo de ping.

🚦 Estados de los dispositivos

Cada dispositivo puede estar en uno de estos estados en tiempo real:

✅
OK
Respondió al último ping. Contador de fallos en 0.
⚠️
Fallos
No responde. Muestra fallos actuales / máximo. Ej: "2/3".
⏳
Apagado
Señal de apagado enviada. Esperando el tiempo de apagado para reencender.
🛡️
Gracia
Reencendido. En período de espera para que arranque sin vigilancia.
—
Inactivo
Vigilancia desactivada por checkbox. No se hace ping.
❓
Sin IP
Slot configurado sin IP asignada. No se puede vigilar.

📡 Configuración de dispositivos

La página principal muestra una tabla con los 16 slots de dispositivos. Cada fila tiene los siguientes campos configurables:

Campo Tipo / Rango Descripción Por defecto
Nombre Texto libre Nombre descriptivo del dispositivo. Aparece en el log y en el estado en tiempo real. Ej: "Cámara Entrada", "Tablero Salón". Vacío
IP IPv4 Dirección IP del dispositivo a vigilar. El Watchdog hará GET http://IP/status cada ciclo. Debe ser una IP fija accesible desde la misma red. Vacío
MAC ESP-NOW AA:BB:CC:DD:EE:FF Dirección MAC del dispositivo destino para el envío ESP-NOW. Se usa cuando el checkbox ESP-NOW está marcado. Se puede obtener del Serial Monitor del dispositivo al arrancar. 00:00:00:00:00:00
Cód ESP Número 0–99 Código de 2 dígitos que se envía por ESP-NOW al actuar. El dispositivo receptor lo interpreta para identificar qué relé debe conmutar. 0
ESP-NOW ☑ Checkbox Activa el envío por ESP-NOW al detectar fallo. Si está marcado, el Watchdog enviará el código ESP al actuar. Se puede usar junto con RF simultáneamente. Desactivado
Cód RF Número largo Código RF 433MHz (mínimo 11 dígitos) que se envía por el transmisor FS1000A al actuar. El receptor RF del dispositivo lo interpreta para conmutar el relé de alimentación. 0
RF ☑ Checkbox Activa el envío por RF 433MHz al detectar fallo. Se puede usar junto con ESP-NOW simultáneamente para mayor fiabilidad. Desactivado
Fallos 1 – 10 Número de pings fallidos consecutivos que deben acumularse antes de actuar. Con 1 actúa al primer fallo. Con 3 actúa si falla 3 veces seguidas. Un fallo puntual de red no dispara la acción. 3
T.Apagado (s) 1 – 60 segundos Tiempo en segundos que el dispositivo permanece apagado (sin alimentación) antes de reencenderse. Mínimo recomendado: 5 segundos. Dispositivos lentos pueden necesitar más. 5
T.Gracia (s) 10 – 300 segundos Tiempo en segundos tras el reencendido durante el cual no se vigila el dispositivo. Imprescindible para que el dispositivo arranque sin que el Watchdog lo vuelva a reiniciar. Una cámara ESP32 necesita al menos 30–60s para arrancar y conectarse. 90
Activo ☑ Checkbox Activa o desactiva la vigilancia de este slot. Si está desmarcado, el dispositivo no recibe pings aunque tenga IP configurada. Útil para dispositivos que no siempre están encendidos (ej: cámaras que se apagan por la noche). Desactivado
Estado Solo lectura Muestra el estado actual en tiempo real: ✅ OK, ⚠️ N fallos, ⏳ Apagado, 🛡️ Gracia, — Inactivo. —
⚠️ Si un slot tiene ESP-NOW y RF ambos activados, el Watchdog enviará AMBAS señales al actuar, lo que aumenta la fiabilidad del reinicio.
ℹ️ Los cambios en la tabla se guardan pulsando "💾 GUARDAR TODOS LOS DISPOSITIVOS". Los datos se escriben inmediatamente en la memoria NVS y persisten tras reinicios.

🌐 Páginas web disponibles

El Watchdog sirve las siguientes URLs en su IP (por defecto 192.168.1.250). Todas requieren autenticación HTTP básica con usuario admin y la contraseña configurada.

GET / Página principal — tabla de 16 dispositivos, estado en tiempo real, botones de navegación
POST /guardarDispositivos Guarda todos los dispositivos de la tabla en NVS. Redirige a la página principal.
GET /config Página de configuración global — WiFi, red, intervalo de ping, contraseña web
POST /guardarConfig Guarda la configuración global en NVS y reinicia el Watchdog para aplicar cambios
GET /log Log de eventos — muestra los últimos 20 eventos en orden inverso (más reciente primero)
GET /borrarLog Borra todos los eventos del log circular. Redirige a /log.
GET /status Devuelve JSON {"status":"ok","uptime":SEGUNDOS} — permite que otros dispositivos vigilen al propio Watchdog

📋 Log de eventos

El Watchdog mantiene un log circular de los últimos 20 eventos en RAM. Se muestra en la página /log en orden inverso (el más reciente primero).

Cada entrada del log contiene: tiempo de uptime cuando ocurrió, nombre del dispositivo y descripción del evento.

Tipos de eventos que se registran

EventoCuándo ocurre
🚀 Watchdog arrancadoAl iniciar el sistema. Incluye la IP asignada.
⚠️ Fallo N/MCada vez que un dispositivo no responde al ping. Muestra fallo actual y máximo.
🚨 REINICIO: N fallos consecutivosAl superar el máximo de fallos y enviar la señal de apagado.
🔛 Reencendido tras XsCuando se envía la señal de encendido tras el tiempo de apagado.
✅ Fin de gracia — vigilancia reanudadaAl terminar el período de gracia. Vuelve a vigilar normalmente.
✅ Recuperado tras N fallosCuando un dispositivo vuelve a responder después de haber tenido fallos.
📝 Config actualizada desde webAl guardar cambios en la tabla de dispositivos o en la configuración global.
ℹ️ El log es circular — cuando llega a 20 entradas, la más antigua se sobreescribe. El log se borra al reiniciar el Watchdog (está en RAM, no en NVS). Para borrar manualmente existe el botón "🗑️ BORRAR LOG" en la página /log.
